# الدفعة الثانية من فحص الموقع

## النطاق

السجل القديم وملفات القراءات، رفض العمليات المحفوظة دون إنترنت، خصوصية بيانات الموظفين، حماية تخمين الرمز، وملاحظات التصميم المؤجلة. بقي تغيير العداد وصيانة الملفات الكبيرة وESLint والتحسينات الإضافية خارج هذه الدفعة.

## السلوك

- «حسابي» يحتفظ بالعمليات المرفوضة على هذا الجهاز، مع تفاصيلها وإمكانية تنزيل نسخة وفتح صفحتها. تنبيه ثابت يوصّل للسجل. الحذف بعد «خلصت مراجعتها» وتأكيد فقط. لا إعادة إرسال تلقائي لعملية رفضها الخادم.
- يُحفظ سجل الرفض قبل إزالة العملية من الطابور؛ إن امتلأ السجل (1000 عملية) تبقى العملية بالطابور. أخطاء الشبكة تبقى معلقة. تحديث صف مخفي بـRLS لا يُعتبر نجاحًا، وتعارض unique لا يُعتبر إعادة إرسال ناجحة إلا إن كان نفس UUID موجودًا.
- تفاصيل الأخطاء لا تحتوي رسالة الخادم الخام، ولا بيانات دخول أو توكنات؛ السجل مقسّم حسب الحساب. طابور الأختام وترتيب عملياته وربط معرّف الدفعة المؤقت يبقيان كما هما، مع حفظ الرفض قبل إزالته.
- قراءة employees الخام للمدير ولصاحب الصف فقط. employee_directory يعيد أسماء العمل المطلوبة، ولا يعيد هواتف الآخرين إلا هواتف الفنيين النشطين لمكتب المهام. تبقى أسماء الفنيين السابقين للسجلات، بدون هواتفهم. لا تُمنح صفحة أو صلاحية تلقائياً.
- «الإعدادات ← الأرشيف والمساحة»: تنزيل الأقدم من سنة؛ حتى 5000 حركة بالملف، والأسابيع المعتمدة القديمة فقط. لا حذف تلقائي عند تركيب التحديث. يجب تنزيل أرشيف وتأكيد حفظه قبل التنظيف. بصمة تمنع تنظيف بيانات تغيرت بعد التنزيل.
- أرشفة القراءات تفرغ نسخة الملف فقط، وتحتفظ بالصفوف والقراءات وهوية الملف. استرجاع JSON من نفس الأرشيف يرجع الملف الأصلي ببصمته ويحافظ على القراءات الحالية. لا تعيد فتح أسبوع أو تعدّل قراءات قديمة.
- أجسام Excel وبيانات الدخول لا تُنسخ في الحركات الجديدة. السجل القديم لا يتغير إلا إذا نزّل المدير أرشيفًا واختار تنظيفه.
- بطاقات الحالة السليمة خضراء، «المزيد» بعنوان وبطاقة مستديرة، إشارة تمرير للجداول، نصوص الأختام والتوزيع الصغيرة لا تقل عن 12px، وشارات الرئيسية لا تُقص. وصف المخزن أزيل؛ بطاقته كانت غير موجودة أصلًا، والجداول القديمة واختباراتها محفوظة.
- نقل الطبلون في نافذة النظام، مع اقتراح المناطق وإلغاء لا يغير شيئاً.

## قيد حماية الدخول على الحقيقي

الدالة `public.password_verification_attempt_hook(jsonb)` لا تستقبل الرمز ولا تخزنه. تستقبل نتيجة تحقق Supabase فقط؛ خمس محاولات خاطئة خلال ربع ساعة تمنع دخولًا جديدًا لربع ساعة، ولا تنهي جلسة مفتوحة. صلاحية تنفيذها لخدمة Auth وحدها؛ لا يمكن للزائر أو الموظف تصفير العداد أو تسميمه.

**رفع SQL لا يفعّل هذه الحماية على Supabase المستضاف.** يلزم من مالك المشروع في Authentication → Hooks تفعيل Password Verification Attempt واختيار الدالة. حسب توثيق Supabase هذه الميزة لـTeams وEnterprise. لا توجد صلاحية إدارة Supabase في البيئة، ولم يُفحص نوع الاشتراك الحقيقي أو إعداد حد الخدمة الحالي. لا يُنشأ اشتراك أو تُغيّر الفوترة. إذا كانت الخطة لا تدعمها تبقى حماية الخدمة الحالية، ولا تُدّعى حماية إضافية على الحقيقي. إعداد Docker المحلي يفعّلها للاختبار فقط.

## الفحص

- فحص الأنواع والبناء ناجحان، 113 اختبارًا آليًا ناجحًا و3 متجاوزة لغياب ملفات Excel الأصلية، و315 فحص SQL ناجحًا. بُني setup.sql من الصفر وأُعيدت الفحوص. أُضيفت حالات لاختلاف البيانات بعد تنزيل الأرشيف، والاسترجاع المعدّل، ومنع الأرشفة لأسابيع حديثة أو مفتوحة، وصلاحيات المدير والفني والزائر.
- واجهة الأرشفة: تنزيل، تأكيد مطلوب، إلغاء يترك الملفات، تنظيف يحفظ القراءات، واسترجاع يعيد الملف نفسه.
- خدمة GoTrue المحلية الفعلية: فشل متكرر، منع رمز صحيح أثناء الحظر، استمرار تحديث جلسة قديمة، ثم دخول ناجح بعد انتهاء المهلة. استدعاء الدالة من عميل عادي مرفوض.
- مهام وأختام دون نت مع رفض من الخادم: التفاصيل تبقى في «حسابي» بعد تحديث الصفحة. عروض 320 و390 و1366، فاتح وداكن، للحساب والإعدادات والمزيد والتقارير وسجل الأختام والتوزيع.
- كل البيانات المستخدمة وهمية على قاعدة محلية مستقلة. لم تُستخدم بيانات التشغيل أو إرسال رسائل حقيقية.

لم يُجرّب جوال حقيقي أو Safari أو طابعة ورق أو SMS حقيقي. حماية التخمين الإضافية غير مفعّلة على الحقيقي، وليست نتيجة نشر تلقائي.
