## 2) ما هو النظام

نظام لإدارة مكتب مخيم 2 (أبناء فارس أبو زايد). واجهة عربية من اليمين لليسار، تعمل كموقع وكتطبيق على الجوال، وتكمل عملها **بدون إنترنت** ثم تتزامن.

| الوحدة | ما تعمله |
|---|---|
| **تقرير التوليد** | محروقات، تشغيل المولدات، الأحمال (المتوسط يُحسب تلقائياً)، صيانات |
| **التوزيع والأحمال** | مناطق، ساعات تغذية، تشغيلات، شريط 24 ساعة |
| **المهام الميدانية** | أوردر للفني على واتساب أو SMS، ورابط «أنهيت» |
| **الحضور والانصراف** | ورقة QR مطبوعة، مرتين باليوم، كشف أسبوعي |
| **المخزن** | أصناف وحركات وتنبيه نقص |
| **الأختام** | رولات ودفعات وفنيون واستخدام، وتعمل بدون إنترنت |
| **التقارير** | أسبوعي وشهري، Excel وطباعة |
| **كشف أعمال الأختام** | أسبوعي/شهري/إجمالي وطباعة |
| **الإعدادات** | الموظفون، الصلاحيات، المسميات، النسخ الاحتياطي |

الأدوار: مسؤول النظام، مدير، مشغّل التوليد، مشرف التوزيع، فني، موظف. والمدير يحدد من الإعدادات أي صفحات يرى كل شخص.

## 3) البنية التقنية (باختصار)

```
الجوال / الحاسوب  ──►  Cloudflare Pages  (يخدم الموقع)
        │
        └──────────►  Supabase  (قاعدة بيانات Postgres + الدخول + التحديث الحي)

GitHub  ──(عند كل رفع)──►  Actions: فحص + اختبار + بناء ──► تحديث قاعدة البيانات ──► نشر الموقع
```

- **الواجهة:** React 19 + TypeScript + Vite، تطبيق PWA، قاعدة محلية على الجهاز (Dexie).
- **الخادم:** Supabase (Postgres 17 + صلاحيات على مستوى الصفوف + دوال آمنة).
- **الأندرويد:** تطبيق WebView يفتح نفس الموقع، ولذلك **يتحدّث تلقائياً مع الموقع**.

### أين كل شيء في المجلد

```
mukhayyam-2/
├─ app/                      الموقع نفسه
│  ├─ src/features/          كل وحدة في مجلد (generation, distribution, tasks, attendance, seals, reports, stock, settings...)
│  ├─ src/ui/                المكونات المشتركة (تأكيد، تنبيه، حالة الاتصال)
│  ├─ src/data/              قاعدة الجهاز والمزامنة
│  ├─ public/                الأيقونات و _headers والـ APK
│  └─ .env.hosting           عنوان Supabase ومفتاحه العام (قيم عامة، ليست سرية)
├─ supabase/
│  ├─ migrations/            تاريخ قاعدة البيانات كاملاً
│  ├─ updates/               ملفات التحديث update-N.sql (تنزل تلقائياً)
│  ├─ setup.sql              ملف التجهيز الكامل لمشروع جديد
│  ├─ apply-updates.sh       يطبّق التحديثات الجديدة فقط
│  ├─ tests/                 فحوص قاعدة البيانات (كلها يجب أن تنجح)
│  └─ local/                 نسخة Supabase محلية للتجربة (Docker)
├─ android/                  مشروع تطبيق الأندرويد
└─ docs/                     هذه الأدلة
.github/workflows/mukhayyam2-deploy.yml    خط النشر التلقائي
```

## 4) كيف يتحدث الموقع «أولاً بأول»

**القاعدة الذهبية:** أي ملف يتغيّر داخل `mukhayyam-2/app/` أو `mukhayyam-2/supabase/updates/` ويُرفع إلى الفرع، ينزل على الموقع تلقائياً خلال دقائق. لا تحتاج أن تفعل شيئاً آخر.

### الطريقة 1: من خلال Claude (الأسهل، وهي التي نعمل بها)

1. تكتب لـClaude ما تريد.
2. يعدّل الكود، يشغّل الفحوص، ثم يرفع (push) على الفرع `claude/youthful-bell-qnhys0`.
3. GitHub Actions يبدأ تلقائياً.
4. بعد دقائق يظهر التحديث على https://mukhayyam2.pages.dev.

### ماذا يحدث داخل Actions (بالترتيب)

1. `npm ci` ثم **فحص الأنواع** `tsc` ثم **الاختبارات** `vitest` (إن فشل شيء يتوقف النشر).
2. بناء النسخة النهائية.
3. **تحديث قاعدة البيانات** (إن كان في `supabase/updates/` ملف جديد لم يُطبَّق بعد، يطبَّق مرة واحدة ويُسجَّل).
4. **نشر الموقع** على Cloudflare Pages بالرابط نفسه دائماً.

### كيف تتأكد أنه نُشر

1. افتح صفحة [Actions](https://github.com/yousefhmm142-cell/yousef/actions/workflows/mukhayyam2-deploy.yml): العلامة **الخضراء** = نُشر. **الحمراء** = فشل (افتحها لترى أي خطوة).
2. ادخل الموقع: خلال دقيقة يظهر **شريط تحديث بالشعار** ويتحدّث لحاله. أو من «حسابي» اضغط **«تحقق من تحديث»**. سطر النسخة هناك يبيّن رقم البناء الحالي.
3. في الأندرويد: نفس الشيء، لا تحتاج تثبيت جديد.

### الطريقة 2: من الحاسوب مباشرة (git)

```bash
git clone https://github.com/yousefhmm142-cell/yousef.git
cd yousef
git checkout claude/youthful-bell-qnhys0
# عدّل الملفات داخل mukhayyam-2/app ...
cd mukhayyam-2/app && npm install && npx tsc -b && npx vitest run
cd ../.. && git add -A && git commit -m "وصف التعديل" && git push
```

### الطريقة 3: تشغيل النشر يدوياً بدون تعديل

من صفحة Actions اضغط **Run workflow** (الخط يدعم `workflow_dispatch`).

## 5) تحديثات قاعدة البيانات

- كل ميزة تحتاج تغييراً في القاعدة تأتي بملف جديد `supabase/updates/update-N.sql`.
- ينزل **تلقائياً** مع الرفع طالما السر `SUPABASE_DB_URL` مضبوط في GitHub.
- يُطبَّق كل ملف **مرة واحدة فقط** ويُسجَّل في الجدول `m2_ops.applied_updates`، وتكراره لا يضر.

### إن ظهرت رسالة «قاعدة البيانات تحتاج آخر تحديث» أو فشلت ميزة جديدة

1. افتح [محرر SQL](https://supabase.com/dashboard/project/aklhimhhwzkdjmxyjahi/sql/new).
2. افتح الملف من المستودع (مجلد `mukhayyam-2/supabase/updates/`)، انسخه **كاملاً**، الصقه، ثم **Run**.
3. النتيجة المتوقعة: `Success. No rows returned`.

| الملف | الموضوع |
|---|---|
| `update-17.sql` | تحديث حي للأختام بين المحاسبتين |
| `update-18.sql` | إضافة أختام جديدة لدفعة من «تعديل» |
| `update-19.sql` | كشف أعمال الأختام (المهام والتقارير) |
| `update-20.sql` | الحضور: موقع المكتب، مرتين باليوم، 60 دقيقة |

## 6) أسرار النشر (مرة واحدة فقط)

من [Settings → Secrets → Actions](https://github.com/yousefhmm142-cell/yousef/settings/secrets/actions):

| الاسم | ما هو | من أين |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | صلاحية «Cloudflare Pages: Edit» | Cloudflare → My Profile → API Tokens |
| `CLOUDFLARE_ACCOUNT_ID` | رقم الحساب | Cloudflare → Workers & Pages (يمين الصفحة) |
| `SUPABASE_DB_URL` | رابط الاتصال بقاعدة البيانات مع كلمة السر | Supabase → Connect → **Session pooler** → URI |

- سر ناقص = خطوته فقط تُتخطى، والبناء والفحص يستمران.
- **أمنياً:** لا تلصق أي مفتاح في محادثة. إن انكشف توكن (حدث هذا مع توكن Cloudflare)، **أنشئ توكناً جديداً** وضعه في Secrets واحذف القديم.

## 7) تطبيق الأندرويد

- الملف: https://mukhayyam2.pages.dev/mukhayyam2.apk (موقّع، من نفس الشهادة).
- يحمّله الموظف ويثبّته مرة واحدة. بعدها **يتحدّث تلقائياً** مع كل تحديث للموقع.
- يعمل بدون إنترنت: يعبّي ثم يرسل لما يعود النت. إن تعطّل على جوال، أرسل لـClaude **نص رسالة الخطأ**.
- إعادة بناء الـAPK مطلوبة فقط إذا تغيّر كود الأندرويد نفسه (مجلد `android/`)، وليس عند تغيير الموقع.

## 8) الاستخدام اليومي (للمدير)

### مرة واحدة بعد التثبيت

1. **الإعدادات ← الموظفون:** أضف الموظفين وأرقام جوالاتهم ورمز الدخول.
2. **المسمى الوظيفي:** اكتب «مدير الموقع» و«مدير المكتب» لصاحبيهما (تظهر أسماؤهما تحت كل كشف مطبوع). التفاصيل: [printed-sheet-signatures.md](printed-sheet-signatures.md).
3. **الإعدادات ← الصلاحيات:** حدد الصفحات لكل شخص (مثلاً صلاحية الأختام لعلياء).
4. **الحضور:** غيّر رمز الحضور الافتراضي `0000`، واطبع ورقة الـQR وعلّقها. اختياري: من جوالك وأنت بالمكتب اضغط «اعتماد مكاني الحالي» لتقييد الـQR بالموقع.

### الطباعة والواتساب

- كل كشف: «طباعة كالورقة» أو **«إرسال واتساب (PDF)»** (التوليد والتوزيع).
- أسفل كل كشف: توقيع مدير الموقع واعتماد مدير المكتب.

### النسخة الاحتياطية

- تلقائية يومياً على الخادم، وزر في الإعدادات ينزّل كل البيانات في ملف واحد.

## 9) للمطور: التشغيل والاختبار محلياً

```bash
cd mukhayyam-2/app
npm install
npm run dev           # تشغيل للتطوير (بدون ملف .env = وضع تجربة بحسابات وهمية)
npx tsc -b            # فحص الأنواع
npx vitest run        # الاختبارات (77 اختباراً)
npm run build         # بناء النسخة النهائية
```

```bash
# قاعدة البيانات: يبني قاعدة مؤقتة ويشغّل كل الفحوص. النتيجة: ALL CHECKS PASSED

# يجمع كل الجداول في setup.sql (بعد تعديل أي migration)
./build-setup.sh
# نسخة Supabase كاملة على جهازك (Docker)
local/apply.sh
```

## 10) حل المشاكل السريع

| المشكلة | الحل |
|---|---|
| عدّلت ولم يتغيّر الموقع | افحص [Actions](https://github.com/yousefhmm142-cell/yousef/actions/workflows/mukhayyam2-deploy.yml). إن كان أحمر افتح الخطوة الفاشلة. وإن كان أخضر: «حسابي ← تحقق من تحديث» |
| الرفع فشل بـ«Internal Server Error» | عطل مؤقت من GitHub. أعد المحاولة بعد لحظات |
| ميزة جديدة تعطي خطأ بالحفظ | ملف التحديث لم ينزل. الصقه يدوياً في Supabase (قسم 5) |
| Actions يفشل في «Update the database» | السر `SUPABASE_DB_URL` غلط أو ناقص (يجب أن يبدأ بـ`postgresql://` وفيه كلمة السر) |
| الموقع يعمل لكن لا ينشر | `CLOUDFLARE_API_TOKEN` أو `CLOUDFLARE_ACCOUNT_ID` ناقص |
| لا يوجد نت عند الموظف | عادي: يعبّي، والنقطة عند صورته **صفراء**، وبعد رجوع النت «جاري المزامنة» ثم «تمت المزامنة» |
| الحضور بالـQR رُفض | بعيد عن المكتب (إن حُدّد الموقع)، أو سجّل مرتين اليوم، أو لم تمرّ 60 دقيقة على الحضور |
